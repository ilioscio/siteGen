# Overengineering a simple html website
I think I resent the wasteful nature of javascript based web technologies, I can forgive javascript when it's used to add logic to webpages that adds functionality that would otherwise be impossible, but it doesn't take much time developing a modern PWA before you start to ask if all the abstractions give us enough for it to be worth it.

## Keep it simple, stupid
So if we're lost let's go all the way back before moving forward, I'm talkin raw HTML and CSS. If we need javascript for something, we'll cross that bridge when we feel like it. But html has a few drawbacks that put us firmly into the 'overengineering' camp, principally that manual editing of html boilerplate is a slog, even if you keep your code clean. 

Also it's a slog to keep an index of all pages updated. We can certainly code those things though which puts us into 'static site generation' territory.

## This is bat country
Well, what *do* I want to write my posts in? If we keep adhereing to K.I.S.S. then i'm banking on markdown for this task. It's got simple formatting, a way to create titles, subtitles, links, images, videos, I can probably inject something special for canvas elements as well. Also I can use any editor I like (neovim), or even just use github's builtin editor to quickly add a post to the repo.

So, the idea is to write markdown posts and then, run my static site generator on the post directory which then generates an html file for each markdown file, and also creates an index of all posts, this is then served by an http server such as....?

## We're not done yet
Who's serving the page though? I can't host servers through my current ISP so i'm stuck using someone else's VPS instances, in the past I've used linode (aka akamai) for this, but upon further investigation, the german based hetzner delivers better performance per cost. 

So get a hetzner instance, and here's the fun part, add keys to the default ubuntu install so that we can use nixos-anywhere to nuke the ubuntu install and put nixos on the machine, this particular nixos configuration has flakes enabled and let's you push the configuration remotely, managing the config entirely remotely. It may have to be remote, but it doesn't have to feel like it. 

This also means that rebuilding the state of the server can be done by running one simple command, security is managed via ssh keys and password login is disabled entirely, fail2ban as well to help with performance against bad actors.

## Fin
Now the last neat piece of the puzzle is that the posts for the site are actually just **bundled** with the site generator, why not? It's my site generator and no one else is gonna use it anyway, it makes everything easier including managing the history of my posts. 

It's all public anyway, if someone else wants to host my thoughts I should be flattered. 

The static site generator also has a nix flake that provides not only the binary for the site generation, but it also runs on the posts directory when it's build by nix, and the output of that is then hosted via nginx. 

Write post > Push to github > update server. Done.
